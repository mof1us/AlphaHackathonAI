# Миграции

Файлы Flyway называются `V1__description.sql`, `V2__description.sql` и т. д.
Все миграции относятся к единственной прикладной базе.
Применение: `./gradlew :data:migrate` из `backend/`, только по явному вызову.

## Схема

- `V1__create_news_and_business.sql` создаёт `news` и `business`.
- `V2__create_parameters.sql` создаёт справочник `parameter_type`, значения
  `parameter_value` и таблицы связей `news_parameter_value`, `business_parameter_value`.

`parameter_type.id` — PostgreSQL enum `parameter_type_enum`, пока с единственной
константой `OKVED`. Миграция также добавляет запись «ОКВЭД» в справочник.
`parameter_value.parameter_type` имеет тот же enum-тип и обязательный внешний ключ
на справочник: каждое значение относится ровно к одному типу.

Связи новостей и бизнесов со значениями параметров — многие-ко-многим (0..N с обеих
сторон). Составные первичные ключи запрещают повтор одной и той же связи.
Удаление новости, бизнеса или значения параметра удаляет соответствующие связи.
Тип нельзя удалить, пока на него ссылаются значения параметров.

ID новостей, бизнесов и значений параметров — `bigint` (`Long` в Kotlin),
с автогенерацией `GENERATED BY DEFAULT AS IDENTITY`. Внешние ключи в таблицах
связей также имеют тип `bigint`.
`news.date` — `timestamptz`; `is_indexed` обязателен и по умолчанию равен `false`.
Текстовые поля хранятся как `text`; описания типов и бизнесов допускают `NULL`,
остальные поля обязательны. Названия из ERD переведены в `snake_case`.

Новые константы enum добавляйте отдельной версионной миграцией
`ALTER TYPE parameter_type_enum ADD VALUE ...`. Запись с новой константой в
`parameter_type` добавляйте следующей миграцией, после фиксации изменения enum.
После применения миграций обновляйте классы через `./gradlew :data:generateJooq`.
